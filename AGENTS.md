## Rules
- Lead validation lives in `src/lib/lead-schema.ts` and is shared by the browser form and the server function, so client and server checks never drift.
- Leads go from the browser to our own `POST /api/submit-lead` (`submitLead` in `src/lib/submit-lead.ts`), never straight to the CRM. The server handler (`src/lib/lead-proxy.server.ts`, routed in `src/server.ts`) takes the visitor IP from Cloudflare's `CF-Connecting-IP` header (then `X-Real-IP` / `X-Forwarded-For`), re-validates with `leadSubmissionSchema`, rate-limits per IP, builds the payload with `toCrmPayload` and sends it to `BASE_ENDPOINT` with `BASE_API_KEY` in `x-api-key`. Those two are server-only env vars: never make them `VITE_*`, or the key ends up in the page bundle. The browser never looks up or sends its own IP.
- Each country (market) has its own route, defined in `src/lib/markets.ts`: `/` is the default English UK page, `/sa` is the Arabic market (RTL; Saudi Arabia, the other Gulf states, Jordan and Lebanon, listed in `MARKETS.sa.countries`), `/sa/en` its English version, and `/it`, `/de`, `/pt`, `/es` are Italy, Germany, Portugal and Spain in their own language (they share the € quiz, `EUR_QUIZ`). All of them render one shared `LandingPage`/`LeadQuiz` with per-page copy objects (and a per-market quiz in `QUIZ` in `lead-schema.ts`), so versions stay in sync. To add a country, add it to `MARKETS`/`PAGES`, its copy, its quiz and its route file.
- `src/server.ts` guards the landing pages before rendering: a per-IP rate limit (`src/lib/rate-limit.ts`, Cloudflare `PAGE_RATE_LIMITER` binding configured in `vite.config.ts`, in-memory fallback), then a country gate (`src/lib/geo.ts`) using Cloudflare's `request.cf.country`. A market page is only served to visitors from one of that market's `countries`; everyone else is redirected (302, query string kept) to their own market's page, or to `/` when there is none. Served pages also get a `visitor_country` cookie (ISO code only, `src/lib/visitor-country.ts`) that `LeadQuiz` reads after hydration to pre-select the visitor's own dial code (`dialCodeFor` in `lead-schema.ts`, e.g. +962 for Jordan; the market's `defaultDial` otherwise). In local dev, add `?geo=SA` to choose a country.
- Production is a Node server (`npm run build` uses Nitro's `node-server` preset by default; `NITRO_PRESET=cloudflare-module` still builds the Worker), run by systemd (`deploy/arabic-trading-spark.service`, 127.0.0.1:3093, env from `.env`) behind nginx (`deploy/nginx-spark.conf`: `/assets/` from disk, everything else proxied). Deploy with `git pull && npm ci && npm run build && systemctl restart arabic-trading-spark`. On Node the rate limits use the in-memory counter.
